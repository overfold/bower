## Summary

Audit 5 found few new structural issues. It focused on correctness and polish: the audit log rendered `[object Object]` for creates, a stale failed deployment still offered a rollback that would downgrade a healthy service, disabled ghost buttons looked more clickable than enabled ones, the command palette pre-selected "Deploy…", and an undeclared color token made meter tracks invisible. That last one led to linting every color utility against `@theme`.

## Finding details

Problem and fix for each finding, as given in the final (audit 6) revision of the report. That revision differs from the first in two places: A5-L3 keeps the "+" on "Attach volume", and A5-V1 was added. A5-V1 had no ID in the report, and the ID was assigned in this record. - **A5-C1 Expanded “created” events show “— → [object Object]”.** scalarDiff is true whenever both keys exist and they are not both objects. Real create events (null before, object after) go through String(), so every create expands to one useless line and the created fields are never shown. The capture triggers this through the real “Create service” flow, not seed data. Fix: Treat a diff as scalar only when neither side is an object. Null before with an object after: render each after field as “— → value” in the same muted-old format S16 decided for updates. Deletes render “value → —”. Add unit tests for create, update and delete payloads.
- **A5-C2 Service CPU card is blank and usage meters have no track.** The skeleton and both tracks use bg-surface-raised, which is not a token, so they are transparent. Until CPU has a second sample (2.5–7.5s after load, or forever if sampling fails) the card shows only its label and footer. The memory bar has no track, so a 28% reading looks like a decorative line. This breaks A4-Q55 (“always draw the track”) and L22 (loading shows a skeleton). Fix: Track bg-line, as in Meter (components/status.tsx). Skeleton bg-sunken plus the text “Measuring…”. Extend the local ESLint rule that enforces the type scale so it also rejects colour utilities not in @theme. A grep found no other unknown colour tokens. Footer “Updated 5s ago” instead of an absolute timestamp, since this is a live reading.
- **A5-C3 An older failed deployment offers “Roll back” as its primary action after a later deployment fixed it.** Storefront v2.4.1 failed at 14:15. The same image succeeded at 15:15 and is running. The 14:15 page still leads with a solid “Roll back to storefront:v2.3.0”, which would downgrade the healthy service. The page never says it was superseded. A fail-then-succeed sequence is normal, so this is not a fixture artifact. Fix: The page already loads journal. If any newer deployment exists for the service and environment, show a neutral notice: “Superseded by v2.4.1 · succeeded 1h ago · View”. For superseded deployments, show no primary button. Keep Redeploy and Edit configuration as default buttons. Test fail → succeed (no primary) and newest fail (primary).

On page 1 the disabled “‹ Previous” has a box and the enabled “Next ›” is bare text; page 2 is reversed. Switch, TabsTrigger, SelectItem and DropdownMenuItem still use opacity-50, a second disabled style. Fix: Move fill and border into the solid variants only (primary, destructive, default). Ghost and link get disabled:text-ink-muted with no box. Pagination per Q14 (you chose: both as text buttons; the disabled one pale, the enabled one brand-coloured). Replace the remaining opacity-based disabled states with text-ink-muted and cursor-not-allowed.

## What was already good

The audit recorded these patterns as working well, to protect them from regression:

- **Needs attention**: One row per symptom, service first, specific ID beneath, one action each. The same component on Home and the project Overview.
- **Compact deployments table**: Home and the project Overview use the compact preset; nothing wraps or scrolls sideways.
- **Inline validation**: Message under the field, red border in every state, no duplicate banner.
- **Focus states**: Inputs and buttons meet 3:1.
- **Unsaved-changes bar**: Counts and Discard; variable edits are staged with the rest of Configuration.
- **Delete project**: Names what goes, type-to-confirm with the slug, solid red only on the final step.
- **Empty project**: Setup checklist that explains why later steps are locked.
- **Domains**: One DNS record open at a time, copy buttons beside their values.
- **Terminal dialog**: Allocation in the title, full screen as an icon, status footer.
- **Failing-service popover**: State, next attempt, failure count, cause and actions.
- **Settings navigation**: Grouped into Personal, Instance and Organization.
- **Not-found pages**: Branded, and show the requested path.
